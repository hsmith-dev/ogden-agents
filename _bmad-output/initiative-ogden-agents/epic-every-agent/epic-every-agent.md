# Add Antigravity beside Claude Code, if possible

## Description

v1 is Claude Code, fully (user, 2026-10-02); every other v1 epic already targets it. This epic adds Google Antigravity as a second chat agent, but only if a spike shows it can be done well and the user says go. Antigravity speaks ACP through Google's own `agy_acp_server` binary, listed in the ACP registry as `antigravity-acp` (1.3.0, proprietary, published 2026-10-02).

Today Ogden Agents has one agent. The server wires a single `AgentPort` (`createClaudeCodeAgent` in `packages/server/src/start.ts`), a session has no agent field, and the web names the agent through constants (`AGENT_ID`, `AGENT_NAME` in `packages/web/src/chat/chat-api.ts`). If the spike is a go, the agent becomes a choice. Each chat picks its agent when it starts, and each project has a default agent that is preselected. The list of agents is agent-neutral data, and each agent declares the permission modes it supports (the standalone per-chat permission modes story defines Ask, Auto and Skip all for Claude Code). The shared ACP client code moves out of `acp-claude-code` first, so Antigravity is one adapter plus one wiring entry (AD-1). Antigravity gets permission cards, resume, and the terminal toggle only if its CLI can resume the ACP session. It is installed as a pinned copy in Ogden's data folder, or an existing copy is used when it matches the pin, never a global install, and it is signed into, or given an API key, from the UI. Where a project turned Planning on, the BMad skills reach it. The herdr-style status sidebar stays on throughout, and every project, Simple or BMad, can hold Claude Code and Antigravity chats at once.

Builds with Antigravity are not in this epic (see Boundaries). Codex, Gemini CLI and Copilot are v2 (epic 8); the research for them is kept in Notes as v2 input.

## Outcome

If the spike is a go: a user picks Claude Code or Antigravity for each chat in any project, with both working at once. CAP-15's v1 success criterion is the signal for chat, and CAP-3's two-agent resume proof is shown with Claude Code and Antigravity. The demo: in one Simple project, an Antigravity chat and a Claude Code chat both run at the same time, and both continue after a server restart.

If the spike is a no-go: the user's decision is recorded and only the Antigravity entries (5, 7, 8) are dropped. The agent-choice groundwork is still built (entries 2, 3, 4, 6, 9 and 10, without Antigravity): `Session.agentId`, the agent registry and agent-neutral agent list with declared modes, the shared ACP client, the picker and the default per project, proven with Claude Code and the fake agent, because v1.1 (Codex and Grok, on `docs/epic-v1.1-codex-grok`) builds on it (user, 2026-10-02). CAP-15's v1 agent is then Claude Code alone, and CAP-3's two-agent proof moves on with the other agents.

### What the research found about Antigravity (2026-10-02, web; the spike re-checks)

- ACP registry: `antigravity-acp` 1.3.0, "Google Antigravity", Google LLC, licence proprietary (terms at antigravity.google/terms). Added to the registry 2026-08-20 (1.0.0); then 1.1.1 (2026-09-03), 1.2.1 (2026-09-23) and 1.3.0 (2026-10-02). It moves fast.
- Distribution: a zip per OS from `dl.google.com/agy-extensions/releases/`, holding `agy_acp_server.par` (macOS arm64 and x86_64; Linux x86_64 and arm64, started with `--uid=`) or `agy_acp_server.exe` (Windows x86_64 and arm64). No npm package and no published checksum, so Ogden pins the URL and its own SHA-256. Sizes at 1.3.0: macOS arm64 about 111 MB, Windows x86_64 about 125 MB, Linux x86_64 about 334 MB. Third-party reports say Linux needs glibc (no Alpine).
- Sign-in: `initialize` advertises `oauth-personal` ("Log in with Google"), `oauth-business` (GCP project and region), `gemini-api-key` and `agent-platform`. It uses the plan of the signed-in Google account (free tier or paid). The ACP server keeps its own credentials and choice under `~/.gemini/antigravity-acp/`; signing into the `agy` CLI does not sign it in.
- Maturity: open Zed issues on Linux: `oauth-personal` waits five minutes for a browser it never opens (1.0.0; the URL goes only to stderr), and a client that calls `session/new` before `authenticate` gets "Authentication required" (1.1.1). Google's Zed page lists macOS and Linux only; Windows binaries exist but no client documents Windows use.
- Sessions and modes (third-party reports only, not seen first-hand): `loadSession`, resume and list are advertised; modes include `default` (asks), `auto-edit` and `yolo` (no confirmation).
