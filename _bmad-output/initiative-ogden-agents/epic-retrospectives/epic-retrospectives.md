# Each finished epic teaches the next one

## Description

In a project where the user turned on Retrospectives (epic 10, AD-22), a finished epic on the board offers **Look back on this epic**. It starts an ordinary agent conversation of kind `planning` in the session view (epic 4's planning session) in which BMad's own retrospective skill reads the epic's evidence (its epic file, tickets, plans, diffs and commits) and writes `epic-<slug>-retrospective.md` beside it, with sourced findings, action items, proposed `AGENTS.md` pitfalls and a verdict. The transcript's document card then offers the two ways the lessons flow back, each an agent conversation the user approves: **Add the lessons to AGENTS.md** (BMad's project-context skill) and **Turn the action items into tickets** (BMad's ticket skill). **Save the lessons for later builds** commits `AGENTS.md` and the retrospective file, so every later build's worktree, which branches from the checkout's last commit, carries the new pitfall. The board shows each epic's verdict. Ogden builds no retrospective logic of its own: it starts the sessions, reads the verdict, and makes one commit on request.

## Outcome

CAP-13's success criterion is the signal: after an epic completes, a retrospective file exists beside it and a later build includes the new pitfall. The second signal is that a project with Retrospectives off, including every Simple project, never shows or runs any of it.

The document card also offers **Turn the action items into tickets**, a planning session invoking the catalog's ticket action on the retrospective file, in which the agent proposes entry and note changes and makes those the user approves through BMad's own ticket tooling; Ogden writes no ticket, and new or changed entries reach the board through the watcher. (CAP-13, CAP-7; AD-10, AD-12)
- E7-R7: The look-back, the lessons and the action-item actions come from fork metadata, not code: a patch to the bmad-method fork on top of 4.5's labels gives `bmad-retrospective` an epic scope (it takes an epic folder and appears on the board's epic header, not in Plan home) and two next steps, and `bmad-project-context` a plain label for recording lessons; tagged, re-vendored with `forks.lock`, and opened upstream. A project on plain upstream BMad shows the reduced-mode notice in place of the look-back action (AD-14). (CAP-13, CAP-18; AD-12, AD-13, AD-14; bmad-integration.md Fork extensions)

## Done when

1. In a project with Retrospectives on, a finished epic is looked back on from the board using only UI chat and buttons, run live with Claude Code, and `epic-<slug>-retrospective.md` exists beside it with its verdict shown on the epic header (CAP-13; E7-R2, E7-R3, E7-R4).
2. A pitfall the retrospective proposes is recorded in `AGENTS.md` and saved from the UI, and the next build dispatched in that project has it in its worktree's `AGENTS.md` (CAP-13; E7-R5).
3. An action item becomes a ticket on the board through an approved ticket session, with no ticket written by Ogden (E7-R6).
4. With Retrospectives off, including every Simple project, no look-back action, offer or verdict shows, a retrospective route is refused with `feature_off`, and nothing is read or written for it (AD-22; E7-R1).
5. A project on plain upstream BMad shows the reduced-mode notice in place of the look-back action (AD-14; E7-R7).
6. The epic's end-to-end suite passes on macOS, Windows and Linux, and it is released in an `ogden-agents` npm version after epic 6's.

## Boundaries

Starting retrospectives and carrying their lessons back. Live checks use Claude Code; because epic 6 ships first, every agent epic 6 supports starts a look-back through its adapter's `skillInvocation` with no code here, and the end-to-end suite runs the look-back against the fake agent only (per-agent checks stay epic 6's). No retrospective logic, scoring or report of Ogden's own, and no editing of `AGENTS.md` or tickets by Ogden: BMad's skills do that through the agent. No automatic or scheduled retrospectives, no headless runs from the UI, no retrospective of a single ticket or an initiative. No in-app viewer for the retrospective file (epic 8, v2): **Open** does what 4.7 decided. Build session transcripts are not handed to the retrospective as session logs in v1 (the skill records the gap). No Needs you or webhook notification for a finished epic (epic 11 owns notifications). The one commit Ogden makes here is **Save the lessons**; it never pushes.
